# Mute Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the operator mute a known outage so its card goes dark red and Telegram stops repeating it, while anything new and substantial un-mutes it.

**Architecture:** A new backend module `mutes` owns one table (`monitor_mutes`, one row per subject monitor) and stateless async functions over the pool. The engine's single record path, the push route, the metric-alert path and backup health call into it to end mutes and to suppress alerts. The monitor listing carries `mute` and `mutedBy`, and every mute change publishes `invalidate`. The dashboard derives "card is muted" from those fields in one pure helper.

**Tech Stack:** Rust (axum, sqlx, SQLite), React/TypeScript (Vite, Tailwind), `node --test` for dashboard libs.

**Spec:** `docs/superpowers/specs/2026-10-26-mute-design.md`

## Global Constraints

- Migration is additive: `backend-rs/migrations/0016_monitor_mutes.sql`; never edit an applied migration.
- Routes are registered in `backend-rs/src/api/mod.rs` and documented in `backend-rs/src/api/openapi.json`. They need the operator token (`flatline_`), like every other operator route. Never describe scoped or read-only tokens: do not copy the "Requires the `write` scope" phrase from neighbouring entries.
- Docs change in the same commit as the behaviour they describe.
- Disk-full level: the monitor's `metric_disk_threshold`, else `90` (the card's "hot" level).
- No backend code connects to client hosts; no agent changes and no agent version bump.
- Commit subjects: `type(scope): summary`, no emoji, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Do not push or deploy; the operator gives that go-ahead separately.
- Checks: `cargo test --manifest-path backend-rs/Cargo.toml`, `cargo clippy --manifest-path backend-rs/Cargo.toml --all-targets`, `npm run test:dashboard && npm run typecheck:dashboard`, `npm run fmt:check` (fix with `npm run fmt`). Never run `cargo fmt` across the tree.

## Review Focus

- A website linked to a muted server through a **group link** going down for the first time (a monitor created later inside that group): the mute must end. Pinned by Task 2's `new_group_child_down_ends_mute`.
- **A backend restart while muted**: the mute is in the database and survives. The disk alert re-sent after the restart must not end it, because the check reads the sample against the snapshot. Pinned by Task 2's `disk_already_full_at_mute_time_does_not_end_mute`.
- **Deleting a monitor that is in another server's snapshot**: the mute must not stay alive waiting for a recovery that never comes. Pinned by Task 2's `deleting_a_snapshot_monitor_shrinks_the_mute`.
- **A host that comes back up while its websites stay down**: the host leaves the snapshot, the card stays muted dark red, and CPU/RAM and backup alerts resume. Pinned by Task 3's `host_recovery_resumes_backup_alerts`.
- **The dashboard reading an older backend** (no `mute`/`mutedBy` fields during a rollout): nothing renders as muted and nothing throws. Pinned by Task 4's `missing_fields_mean_not_muted`.

**Interfaces:**

- Produces (all in `crate::mutes`):
  - `pub struct Mute { pub subject: i64, pub muted_at: String, pub monitors: Vec<i64>, pub smart_failed: Vec<String>, pub full_mounts: Vec<String> }` with `pub fn host_muted(&self) -> bool` (`monitors.contains(&subject)`) and `pub fn to_json(&self) -> Value` → `{"mutedAt", "monitors", "hostMuted", "smartFailed", "fullMounts"}`.
  - `pub const DISK_FULL_DEFAULT: f64 = 90.0;`
  - `pub fn smart_failed(sample: &Value) -> Vec<String>`: `smart.disks[]` entries with `health == "failed"`, by `device` (fallback `"disk"`), sorted and deduped.
  - `pub fn full_mounts(sample: &Value, disk_threshold: Option<i64>) -> Vec<String>`: `disk[]` entries whose finite `percent` ≥ threshold (or `DISK_FULL_DEFAULT`), by `mount`, sorted.
  - `pub async fn get(pool: &SqlitePool, subject: i64) -> sqlx::Result<Option<Mute>>`, `pub async fn list(pool: &SqlitePool) -> sqlx::Result<Vec<Mute>>`.
  - `pub async fn card_monitors(pool: &SqlitePool, subject: i64) -> sqlx::Result<Vec<(i64, i64)>>`: `(id, latest status)` for the subject and its resolved links (reuse `links::resolve`; map its `ApiError` to `sqlx::Error::Protocol`).
  - `pub enum MuteError { NotFound, NothingDown, Db(sqlx::Error) }`.
  - `pub async fn mute(pool: &SqlitePool, subject: i64, sample: Option<&Value>, disk_threshold: Option<i64>) -> Result<Mute, MuteError>`: snapshot = the down ids from `card_monitors`, plus `smart_failed`/`full_mounts` of `sample`. Upsert (replace) the row. `NothingDown` when no id is down.
  - `pub async fn unmute(pool: &SqlitePool, monitor_id: i64) -> sqlx::Result<Vec<i64>>`: deletes the subject's own row and every row whose snapshot contains `monitor_id`. For a group, also every row whose snapshot contains one of its leaf descendants. Returns the deleted subjects, sorted.
  - `pub struct Coverage { pub mutes: HashMap<i64, Mute>, pub muted_by: HashMap<i64, Vec<i64>> }` and `pub async fn coverage(pool: &SqlitePool) -> sqlx::Result<Coverage>`. `muted_by` maps each snapshot monitor to its subjects. It also maps each **down** group whose every down leaf descendant is covered (at least one) to the union of those subjects.
  - `pub async fn is_covered(pool: &SqlitePool, monitor_id: i64) -> sqlx::Result<bool>` (same rule as `coverage`, groups included) and `pub async fn host_muted(pool: &SqlitePool, subject: i64) -> sqlx::Result<bool>`.
- Produces (HTTP):
  - `POST /api/v1/monitors/{id}/mute` → `200 {"ok":true,"id","mute":Mute::to_json}`, `404` for an unknown id, `400` (`ApiError::bad`) when nothing is down, with the message "Nothing on this monitor is down, so there is nothing to mute."
  - `DELETE /api/v1/monitors/{id}/mute` → `200 {"ok":true,"id","unmuted":[subjects]}` (an empty list is fine; idempotent), `404` for an unknown id.
  - Both call `state.events.invalidate()` when something changed.
  - Every monitor object from `GET /api/v1/monitors` and `GET /api/v1/monitors/{id}` gains `"mute": Mute::to_json | null` (its own mute as subject) and `"mutedBy": [subject ids]` (always an array). Compute `coverage` once per request, not per monitor.

**Files:**

**Interfaces:**

- Consumes: Task 1's `Mute`, `card_monitors`, `smart_failed`, `full_mounts`.
- Produces:
  - `pub async fn on_status(pool: &SqlitePool, monitor_id: i64, status: i64) -> sqlx::Result<bool>`. For `DOWN`, delete every mute whose card includes `monitor_id` but whose snapshot does not. For `UP` or `MAINTENANCE`, remove `monitor_id` from every snapshot, and delete a mute left with no monitors. `PENDING` changes nothing. Returns whether anything changed. Only subjects with an active mute are resolved.
  - `pub async fn on_sample(pool: &SqlitePool, subject: i64, sample: &Value, disk_threshold: Option<i64>) -> sqlx::Result<bool>`. It returns at once when the subject has no mute. It deletes the mute when `smart_failed(sample)` or `full_mounts(sample, ..)` holds an entry the snapshot lacks. It drops snapshot mounts that are no longer full. Returns whether anything changed.
  - `pub async fn forget(pool: &SqlitePool, ids: &[i64]) -> sqlx::Result<bool>`: removes the ids from every snapshot and deletes mutes left empty.
