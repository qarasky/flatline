# Performance and reliability audit — October 2026

Audit of `master` at `ba6cfc80` (2026-10-20), covering the Rust backend, the Go
agent, the React dashboard and the deployment. Each finding was verified against
the code; query plans were checked with `EXPLAIN QUERY PLAN` against a database
built from the migrations. `go vet` and `go test` passed at the time of the audit.

Findings are grouped by area and numbered so commits can reference them
(`fix(S1): …`). Severity is High, Medium or Low; nothing was Critical.

## The compound failure

Several findings combine into one chain, and it is the most important thing in
this document:

1. Something holds SQLite's single write lock longer than `busy_timeout` (5 s):
   the one-statement heartbeat prune (S2), the hourly rollup's full scans of
   `metrics_hourly` (S4), a monitor delete cascading through its telemetry (S5).
2. Telemetry `store()` fails, and the push route answers **400** (S1). The agent
   treats 400 as permanent and discards the sample (G4) — the backlog is lost.
3. `verify_token` maps the database error to "invalid" (A1); every SSE stream
   sends `unauthorized` and every dashboard and wall signs out.
4. Check loops fail to record their heartbeat, so a real UP→DOWN transition
   sends no alert (E10).

The agents' synchronized, 20×-rate backlog drain after an outage (G3) makes step
1 more likely exactly when the data is most at risk.

## What is done well

- Drift-free, non-overlapping check scheduling on a monotonic clock; hard
  timeouts on HTTP, ping (with `kill_on_drop`) and Telegram.
- Bounded inputs: 256 KB push bodies, 64 KB payloads, SSE caps per token and in
  total, capped pagination and history ranges.
- Rollups are idempotent upserts and raw rows are pruned only after proven
  folding; `metrics_raw` has covering time indexes.
- The agent's disk buffer is byte-capped with oldest-first eviction and atomic
  writes; self-update staging verifies SHA-256 and runs the staged binary first.
- The dashboard's live client has a silence watchdog, jittered backoff and clean
  unmounts; the documented backup uses the SQLite backup API plus
  `integrity_check`.
